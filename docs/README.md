# 文档导航

本页说明项目中各 Markdown 文件的主要读者和维护时机。

| 文件 | 主要读者 | 用途 | 何时更新 |
|---|---|---|---|
| `README.md` | 你、GitHub 访客、面试官 | 项目入口、功能、构建方法和演示结果 | 每个阶段完成后 |
| `TODO.md` | 你和 Codex | 跟踪当前任务与后续任务 | 每个小目标完成后 |
| `DAILY_PLAN.md` | 你 | 记录每日目标、步骤和验收结果 | 每天开始和结束时 |
| `LEARNING_LOG.md` | 你 | 记录学到的知识、错误和薄弱点 | 每次学习或排错后 |
| `DECISIONS.md` | 你、协作者、面试官 | 记录技术选择、理由和影响，避免以后忘记为什么这样设计 | 做出重要技术选择时 |
| `docs/architecture.md` | 你、GitHub 访客、面试官 | 描述系统模块、依赖关系和数据流 | 架构发生变化时 |
| `docs/ros2_notes.md` | 你 | 整理与项目直接相关的 ROS 2 知识 | 学到新概念后 |
| `docs/troubleshooting.md` | 你和协作者 | 记录错误现象、根本原因和验证过的解决方法 | 每次解决真实错误后 |
| `docs/interview_notes.md` | 你 | 整理项目介绍、面试问题和不同深度的回答 | 每完成一个核心模块后 |
| `AGENTS.md` | Codex 和其他协作代理 | 约束代理如何修改、测试和讲解本项目 | 协作规则变化时 |

各资源目录中的 `README.md` 用于说明该目录未来应保存什么，避免出现含义不清的空目录。
